## Validation Rules

- Structured tests are necessary but not sufficient; every completed task should also include a behavior validation of the real command path when one exists.
- Prefer the smallest validator that can falsify the current change, then rerun that same validator after the fix.
- Runtime failures should name the missing file, setting, command, or dependency clearly.

## Formatting

- Python files written or edited by the agent are expected to pass through `ruff format` via the post-write hook in `.claude/settings.json`.
- Keep formatting scoped to touched files and avoid reformatting unrelated areas of the repository.

## Helper-Agent Use

- Use helper agents for focused read-only work such as repository exploration, research, or related-link discovery.
- Bring useful results back into repository artifacts so they remain visible after the chat ends.

## Related-Link Discovery

- When the task calls for supporting references, spawn one helper run with the objective `find related links`.
- Prefer repository-local paths first, then include authoritative external links when they materially improve the artifact.

## Safety and Sharing

- Never commit secrets, credentials, or populated `.env` files.
- Share placeholder-only configuration through `.env.example` and keep machine-local state out of version control.
- Do not overwrite unrelated local changes. If they conflict with the current task, stop and ask before proceeding.

## Commit Behavior

- Create short Conventional Commits after the validator passes for the current task.
- Stage only files that belong to the active task so unrelated worktree changes stay isolated.
